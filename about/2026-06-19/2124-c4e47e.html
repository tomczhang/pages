mdsite — Project Overview

2026-06-19

mdsite — turn Markdown into your own shareable web report

One command turns a piece of Markdown / chat content into a polished, shareable HTML page, deployed to your own GitHub Pages.

Why

A very common need: turn the conclusions, designs, or weekly updates from a conversation into a good-looking page you can just send a link to. Existing internal tools are tied to private infrastructure, can't be used externally, and carry IP baggage.

mdsite is a clean-room rewrite of that capability, with the infra swapped for each person's own GitHub:

  • No server, no CI to set up — pushing to GitHub Pages deploys automatically.
  • The maintainer hosts nothing — what you publish lives only under your own GitHub account, so this is a tool, not a platform.

Try it

# 1) Initialize (create/reuse a pages repo on YOUR GitHub + enable Pages)
mdsite init

# 2) Turn a Markdown file into an online report
mdsite publish notes.md --title "My Weekly" --category report --summary "This week"
# → prints the real URL: https://<you>.github.io/<repo>/report/<date>/<slug>.html

The site root https://<you>.github.io/<repo>/ is the timeline of all your reports; items older than 30 days auto-collapse.

Install

npm i -g mdsite      # or npx mdsite <command>
mdsite --help

Auth is a one-time thing — no SSH key, no GitHub Action needed. Least-privilege recommended:

  1. gh auth login (preferred; token never written to any file)
  2. fine-grained PAT scoped to that one pages repo (Contents + Pages + Administration: write)
  3. classic repo PAT (fallback; note it grants read/write to all your repos)

Features

  • md / html dual input: Markdown is converted to HTML, or pass through your already-built rich HTML.
  • Single self-contained file: the output is one .html, with Tailwind + Alpine via public CDN — naturally easy to share.
  • Timeline home: reports newest-first; items older than 30 days collapse — computed at view time by current date, never frozen at publish.
  • Safe multi-device merge: concurrent publishes from multiple machines semantically merge pages.json with no lost entries.
  • Credentials never persisted: the GitHub token is injected only via subprocess env, never written to .git/config or logs.
  • Overwrite protection: won't clobber an existing Pages site, and won't touch an existing repo's main branch.
  • Layered templates: built-in templates can be overridden from ~/.mdsite/templates/.

Privacy

Your content is yours.

  • Every page is deployed only to the GitHub repo you configure, served by your own GitHub Pages, using your own credentials.
  • The tool makes no requests to any maintainer-operated backend; the maintainer hosts, caches, and aggregates nothing.
  • The home index lists only your own site's reports — there is no cross-user aggregation entry or central service of any kind.
  • That makes mdsite a tool author (like Hugo / Jekyll), not a platform operator.
